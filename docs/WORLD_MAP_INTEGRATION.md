# World map integration (wide Pattaya world)

Data for a client world-map / GPS UI covering Naklua to Jomtien. Generated by
`tools/mapgen/export_roblox.py tools/mapgen/config/pattaya_wide.json` into
`build/pattaya_wide/roblox/worldmap.luau` (~24 KB). Nothing here has been imported into Studio or playtested yet.
Map data © OpenStreetMap contributors (ODbL 1.0); the module carries the attribution string, show it in the map UI.

## Where it goes
`ReplicatedStorage.PattayaWorldMap` (ModuleScript, source = `worldmap.luau`) so the client map UI can `require` it.
It holds no server secrets and only static data.

## Format (`worldmap.luau`)
All coordinates are **world studs**: x east, z south, i.e. map-local gameplay coordinates + `PattayaBuilder.ORIGIN`
(20000, 0, 0). Flat number lists are `x1, z1, x2, z2, ...`.

```lua
return {
  version = 1,
  attribution = "Map data (c) OpenStreetMap contributors, ODbL 1.0",
  origin = { x = 20000, z = 0 },                       -- PattayaBuilder.ORIGIN (subtract for map-local)
  bounds = { minX, maxX, minZ, maxZ },                 -- all roads of the wide graph
  roads = { { tier = 1|2, name = "Sukhumvit Road"|nil, pts = {x, z, ...} }, ... },
        -- tier 1 = express (Sukhumvit), 2 = main roads; edges of the same name merged, Douglas-Peucker 6 studs,
        -- pieces under 60 studs dropped (100 polylines, ~615 points). Sois are NOT included (draw from graph if needed).
  coast = { {x, z, ...}, ... },                        -- coastline, Douglas-Peucker 8 studs
  districts = { { id, name, nameTh, x, z, poly = {x, z, ...} }, ... },   -- label point + outline (see below)
  pois = { { id, kind, label, x, z, district, order?, status?, graphNode? }, ... },
}
```

## GPS routing across the city graph
- Route finding stays on `ServerStorage.PattayaData.graph` (`PattayaRoute.luau`). For the wide world the leader
  replaces that module with `build/pattaya_wide/roblox/graph.luau` **plus** its sibling modules `graph_part_1`,
  `graph_part_2` (graph.luau appends them; `require(graph)` still returns one `{nodes, edges}` table, so PattayaRoute
  needs no change to load it).
- Index stability: nodes `1..graph.baseNodes` and edges `1..graph.baseEdges` are exactly the central graph in the
  same order (checked: node list prefix and all 614 edge lines identical). New nodes/edges come after.
- Client map line: the server already sends route polylines (`PattayaRoute.polylineOf`) in map-local coordinates;
  add `origin` to draw them on this map.
- **Needed before the wide graph goes live (Luau owners):**
  1. `PattayaRoute.dijkstra` scans all open nodes for the minimum (O(n²)). With 2,925 nodes instead of 463 that is
     ~40x more work per route; add a binary heap and/or stop at `maxLen` before importing the wide graph.
  2. Road Fight courses are "same start + same seed": with more nodes the candidate list and distances change, so
     the tested boss courses would change. Restrict boss course search to `node <= graph.baseNodes` and
     `edge <= graph.baseEdges` (the central graph) to keep them identical.

## The future Bira corridor
- The corridor team (tools/circuit) builds `corridor_graph_game.json` in the same schema, same origin_utm,
  compression 0.5, 0.28 m/stud; node ids are OSM node ids.
- To merge it into the wide world add it to `merge_graphs` in `pattaya_wide.json`:
  `"merge_graphs": ["build/bira/corridor_graph_game.json"]` (path relative to the repo root; copy the file into
  this checkout's `build/` first) and rerun the pipeline from `road_graph.py`. Rules in `road_graph.py`:
  corridor edges already present (same id or same way + end nodes) are skipped; corridor edges whose middle lies
  inside the wide-world polygon are dropped (the city graph wins there, no doubled streets); the rest are appended
  and join the city graph where they share OSM node ids. The script prints how many shared nodes it found — if it
  is 0 the corridor does not connect (its first node east of Sukhumvit must be a node of the wide graph).
- Recommended join for the wide world: the corridor's westernmost node **on Sukhumvit Road** (e.g. the Pattaya
  Klang / Sukhumvit junction, OSM node 4446016998, currently a wide-graph node). The corridor's present join node
  423748313 (east end of Pattaya Klang Road in the central slice) also exists in the wide graph, but the stretch
  between it and Sukhumvit is now city road and will be dropped from the corridor by the rule above.
- After the merge, move `layout.bira_entrance.osm_node` to the corridor's first node outside the city and set
  `status` to `"open"`; then the `bira` POI's `graphNode` is a real routing target for the GPS.
