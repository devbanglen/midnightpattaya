# Decisions, contract, gates (all routes)

How a project stays steerable while agents and GPU boxes produce thousands of assets. Applies to every route.

## Decision log
- **Every product decision gets a row in an append-only `docs/DECISIONS.md`** (A-numbers, date, topic, decision, reason). Never edit an old row; a change of mind is a new row naming the one it replaces. Read it before changing direction. (aroa A001–A114; kit `templates/DECISIONS.md`)
- **Log the decisions that are easy to forget:** third-party use per asset class (aroa A029), GPT budget (aroa A036: no cap, but every call logged), when the owner waives per-concept approval, which kit tag and route the project started from (kit template row A001). (aroa)
- **Owner questions go out as a decision request,** not as a guess: notify, wait, then log the answer. (aroa CLAUDE.md "Notify the owner")

## Contract first
- **Fix the contract before the first render:** camera pitch, `px_per_bu`, frame/origin, tick length, dirs, layer list and z ladder in a `MANIFEST.md` that every producer and reader obeys; changes go in as numbered change requests and become resolutions. Done when a mock set plays in the studio. (aroa MANIFEST v1, 2026-10-08; kit `templates/MANIFEST.md`) Routes: sprite routes; a 3D realtime project writes the same kind of contract for models (units, rig, sockets, clip names, LOD).
- **Readers ignore unknown keys;** producers add informational fields freely, changing a field's meaning needs a CR. (aroa)

## Gates mindset
- **Golden sample first.** 1–3 approved samples per category/archetype before mass production; review the rest on contact sheets. Once the user trusts the pipeline they may waive per-concept approval and review afterwards; log that decision. (aroa)
- **Every complaint the eye finds becomes a gate.** Border touch, pose mismatch, collapsed anchors and head pitch all started as a "looks wrong" and became automatic checks. (aroa check_edges history)
- **A gate is red or green, and "done" means green:** a render is not done until the gate passes on the published copy; publishers gate before publish and quarantine failures with reasons, so one bad design can't turn the release red overnight. (aroa; kit `tools/pipeline/items/wave2/quarantine_w2.py`; details in (sprite-pipeline route doc, not copied)
- **Judge by output files, never by a wrapper's last log line:** Blender exits 0 when its script fails; a job counts as done only when its outputs exist and its fingerprint matches. (aroa A072; details in [gpu-server-setup-fleet.md](gpu-server-setup-fleet.md))
- **Gate evidence is tied to the file version** (size + mtime + sha per set in a ledger), so "gated" can be told apart from "repacked after the gate". (aroa asset release v1)
- **Catch it before the mass render, not after:** run cheap checks on the posed skeleton before any job is queued, then show a golden sample of ~6 representative rigs in the game. aroa A136: of 13 problems found after mass renders, 9 were catchable automatically before rendering and the other 4 by eye in such a sample. Each one had cost a re-render wave. Route details: (sprite-pipeline route doc, not copied).

## Pipeline shape
- **Single source of truth chain:** catalog CSV → job manifest → per-item pack. Nothing is produced without a catalog row that has a name and design notes. (aroa items/monsters)
- **Determinism:** same inputs → byte-identical outputs. This is what makes cross-GPU verification, resumable done-markers and "re-render only what changed" possible. (aroa: 770 files byte-identical across renders, 1,802 frames across boxes)
- **Core ownership:** one agent owns the core render files; others extend through overlays (`config.d/*.json`), hook registries (`pose_modules`, `anims/`), their own subfolder and their own box root. Index files are merged: each writer replaces only its own ids. (aroa)
- **Version per unit of change:** a stamp that covers more than what changed turns every small fix into a whole-library release, and release overhead then dominates the render. aroa: one pose hash per set; a 7-key fix = ~12 box-minutes of rendering but restamp ~4,200 sets + ~2 h repack + ~50 min full gate. Stamp per clip, keep a sidecar ledger for released files, and size releases by what changed. (aroa A134/A136; (sprite-pipeline route doc, not copied)
- **Measure before you scale:** seconds per frame (or per mesh) and whether the box is GPU- or CPU-bound decide the box type, slot count and plan; measure on the real path at full concurrency. (aroa fleet; [gpu-server-setup.md](gpu-server-setup.md))
- **Game data derived from assets says what is drawable:** a generated item row carries its equip classes as body ids (`jobs`, only classes whose sprite exists; the design list kept in `jobs_catalog`), a `body_by_job` template for family/2h bodies and a `fallback`, so a ref gate can expand `{body}` over real combos only. Regenerating restores grants by itself as sets publish. Append-only tables (row index = id) pin rows already appended, so the generator never reorders them. (aroa A116 check_refs: 1,080 "unpublished" refs came from expanding every item over all 16 bodies)

## Data-to-asset reference gate (release)
Before freezing an asset release, resolve every sprite reference in the game data exactly the way the client does (same id templates, same body/gender expansion, same fallback rule) against the *deploy pack list* (published, not deprecated): a ref that is not published, deprecated, or not packed is a failure; a ref that only resolves through a fallback is a failure for the freeze. Expand body templates only over the bodies that may equip the item (a per-row `jobs` list beats a type/slot table beats "all bodies"); without equip rules the gate over-counts (aroa A116: 1,080 -> 70 once rows carried `jobs`). Also check plain id refs (shops, loot, recipes) against the item/monster tables. Source: aroa `tools/release/check_refs.py` (route-independent).
Run the gate as a dry run against the *post-window* state before a publish that deprecates sets: assume the window's id lists published and its deprecation lists deprecated, and use the pack list the window will produce. A deliberate runtime fallback (e.g. garments falling back from a weapon-variant body to the class body, `item.<id>@{base}`) may be accepted per slot, but a fallback whose target is itself deprecated hides the layer: count those as unresolved (hidden), then either render, hold the body on the row (`held_bodies`), or drop the item from the release. (aroa A127: deprecating 2,342 old per-body items left 35 garment refs on class bodies with no v2_5 set; the variant-to-class fallback could not cover them)
- Pre-publish staging check (every lane runs it before the swap, exit 1 = refuse): each staged set's manifest `id` equals its directory name (raw renders can carry the rig/build id, e.g. `knight-greatsword_m`, until a prep step renames it, so the check proves the rename happened); every cross-set reference in the manifest (`weapon_set`, `base`, `holdout_body`) resolves in staging ∪ the published non-deprecated tree; plus release-specific required fields (e.g. per-dir placement tables on every head-swap body). Keep the rules in the release scope file so the release plan applies the same rules to the published tree as blockers. Source: aroa `tools/release/prepublish_check.py`.
- **Pose-code swap race (aroa v2_5):** the renderer compiled the clips at start but hashed the pose files for
  `pose_version` at the end. A job that straddled the in-place swap of a runtime pipe (v2_4 → v2_5 files) wrote old
  poses stamped with the new version, and no gate saw it. Before swapping a live pipe, drain or pause its jobs
  (or swap atomically: new dir + symlink flip). Re-render anything whose log starts before the swap but whose stamp is
  new. Spot-check one clip the release changed (an anchor value) instead of trusting the stamp. Lanes that render
  later on the same pipe should check the pipe hash per job before starting (WAIT, not run). Kit v3 `tools/release/runtime_swap.sh` swaps atomically and refuses while any Blender uses the runtime.
- Partial pose bump without re-rendering every layer ("pose_compat"): an old layer may stay on a new body only with a manifest flag naming the new body code and the clips to hide; the gate accepts the pose mismatch only for that one bump, when the hidden clips cover every clip that changed for that set (from the render plan) and every shown clip's body sockets match the new body within tolerance (skip sockets owned by the held item, e.g. weapon tip). Layers that would be hidden in stand/walk are effectively invisible: list them as hold candidates. Always test negatives (wrong clip list, wrong code, unflagged). Also: after publishing via links/copies, compare per-file sha256 of each published set with its staging copy. Source: aroa CR PC1, tools/release/pose_compat.py, pub_link.py verify (A116).
- Partial body bump (only some rigs get a new pose code, e.g. a neck patch): derive the layer scope from the published index (every non-deprecated set whose `base` is a moved body), never only from each layer owner's own lists; diff that scope against the owners' re-render + restamp lists before the window. aroa v1.1 (A133): 22 per-gender P1 weapons on moved bodies were in nobody's list and turned the post-publish full gate red.
