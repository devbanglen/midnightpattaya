# Performance budgets (all routes)

Origin: aroa A073–A076, A080, A084, A102 (web MMO, Phaser 4, 200 players per map channel). The principles apply to
every route; the sprite-pack sections apply to the sprite routes (3d-sprite, 2d, redesign → sprites); a 3D realtime
client needs its own pack design (sprite-pipeline route doc, not copied).
Kit: `docs/reference/PERFORMANCE.md` (aroa's full budget doc, Thai), `docs/reference/performance/` (playbook: maps,
render scale, client runtime traps), `tools/release/gamepack/`, `tools/release/crowd_mem.py`, `game/shared/`.

## Principles (aroa performance playbook)
1. **Set the budget before building, not after measuring.** Every tier has numbers (frame time, GPU MiB, draw calls, "walkable" and "full view" download, heap); every new asset, map, effect or system states which budget it spends. (aroa A073)
2. **One source asset per object; tiers differ only at runtime:** lod levels built automatically, game rules (view cap + "+N", look budget, crowd mode), a style shader. Never render per-tier copies: double production cost and the copies drift. (aroa A075/A076)
3. **Measure on real GPUs only:** the lowest supported iGPU + a dGPU + a software floor as separate profiles, with the renderer name logged on every row. SwiftShader / headless-VM fps is never a budget number (skill `chrome-gpu-bench`). (aroa A080, A084)
4. **The build gate enforces budgets:** over budget = red build, not a report line. (aroa map gate, game pack gate)
5. **Static beats moving:** bake shadows, light and detail into images; no runtime lights, no full-screen shaders. (aroa map pipeline)
6. **Stream by camera:** load what is visible plus a margin, release what is far, decode off the main thread, compile shaders before the scene. (aroa A080)
7. **Effects and particles declare a low-tier variant** up front. (aroa CLAUDE.md hard rule)
8. **The real driver is the number of distinct looks on screen, not the sprite count:** per-body layers (`item@body`) share almost no texture in a town, so memory, download and draw calls grow with looks. Make the look budget a game rule (full look for party + nearest N, base look for the rest, hide past the view cap). (aroa PERFORMANCE §0)
9. **Don't carry studio shortcuts into the game:** per-frame canvases, CPU dye per (frame, colour), CPU glow blur, one `Text` per player, loading every page. (aroa PERFORMANCE §0)

## Tier budgets (aroa example; set your own numbers in the project's `docs/game/PERFORMANCE.md`)

|---|---|---|---|
| fps / p95 frame time | 30 steady in crowds (33.3 ms), 60 when quiet | 60 / 16.7 ms | 60+ |
| frames > 50 ms | ≤ 1 per minute | ≤ 1 per minute | ≤ 1 per minute |
| renderScale cap | 1.0, backing store ≤ 1.05 Mpx (1080p → 0.70, A102) | 1.5 | 2.0 |
| draw calls / quads per frame | ≤ 120 / ≤ 2,500 | ≤ 250 / ≤ 5,000 | ≤ 500 / ≤ 10,000 |
| GPU textures total (sprite pool / map ground) | ≤ 256 MiB (160 / 48) | ≤ 640 MiB (384 / 128) | ≤ 1.2 GiB (768 / 256) |
| JS heap | ≤ 300 MB | ≤ 500 MB | ≤ 800 MB |
| view cap / full looks (A080) | 40 / 12 | 80 / 24 | 120 / 48 |
| crowd mode (A076) | view cap 30, full look ≤ 10 | 80 | 120 |
| animated FX on screen | 4 | 12 | 24 |
| download until walkable / full view (A084) | ≤ 2 MB / ≤ 8 MB within 10 s | | |
| per-map caps (map gate) | walkable ≤ 1.0 MB, lod1 pack ≤ 3 MB, map GPU ≤ 48 MiB, ≤ 8 draw calls | 128 MiB, 10 | 256 MiB, 12 |
Targets: 200 players per map channel (hard cap 250), designed for 1366×768 and 1920×1080 laptops and 844×390 phones landscape. An iGPU at 1920×1080 is fill-bound (map-only p95 ~31 ms on a UHD 770 whatever the layout): fix it with renderScale or a frame cap, not by cutting content (aroa A102, map pipeline).
- **Town size is cheap when the extra is scenery:** a 90×70 Roman town (palace, 2 temples, 30 villas, 120 cypress, 330 prop instances, max 96 per view, 3 prop pages) measured map-only p99 10.3 ms at 1366×768 and 14.9 ms at 1920×1080 on a UHD 770, vs 9.7 / 12.6 ms for the 49×41 town. Budget per view, not per map; keep service NPCs on the plaza so walk times don't grow with the map. (aroa A110, route 3d-sprite maps)

## Sprite routes: image format, game pack, runtime (moved from the manifest schema)
- **Image format for the game (aroa measured 2026-10-12, 6 sample sets):** keep lossless PNG atlases as the master. WebP lossless is pixel-exact and 0.70–0.76× the bytes (grey hair + masks 0.48×) but decodes 1.1–2.1× slower in Chromium; use `method 4` (0.74×, ~5 s/set) not `method 6` (0.70×, 25× slower, ~110–220 s/set), and only as a deploy-time derivative. A 256-colour palette PNG is 0.2× and decodes fastest but is lossy for toon renders: pages hold 2k–130k distinct colours (outline AA, alpha edges), so PSNR 33–35 dB, max dRGB ~30, edge alpha off by ~8 levels, and it **breaks luminance-ramp dye** (grey levels per hair frame 124 → 18, dyed colour off by up to 14.5). GPU memory is the same for every file format (RGBA8 = page w×h×4); the GPU levers are trimmed atlases (5–25× less than full frames), per-clip page loading and compressed GPU textures for huge mounts (a 960-px dragon set is ~270 MiB RGBA8). Tool: kit `tools/release/format_bench.{py,mjs}`.
- **Game pack = a derived deploy artifact, not a new contract** (aroa CR GP1, A075; `tools/release/gamepack/build.py`, reader `game/shared/assets/gamepack.ts`). Build it deterministically from the frozen PNG master, outside the project: one page per (clip, dir, lod) (clips < 64 kpx over all dirs: one page), `lod0` = master pixels + `lod1` = 0.5× per frame in premultiplied alpha on the even-aligned box (origins even → halve exactly), content-hash file names, compact meta + lookup shards instead of the big index. Measured on 61 sets: lod1 = 0.33× bytes / 0.27× GPU of lod0; per-dir pages of a body walk 0.70 → 0.19 MiB (lod1); the 960-px dragon 269 MiB → 178 (lod0, no shadow) → 45 (lod1). Gate in the build: lod0 decoded back pixel-identical to the master, key counts equal, lod1 rect = lod0/2 ±1.
- **Check whether the shadow layer is constant**: in aroa every frame of a set held the same oval (and bodies shared it pixel for pixel), yet it was packed per frame: 15 % of a body's GPU, 30 % of a large mount's. Strip it in the pack, keep `{w,h,ox,oy}` and draw one shared soft texture in a ground pass. Better: never render shadow per frame in a new project.
- **Masks beside RGBA** (`[RGBA | mask]`, same rect, mask in RGB with A = 255 so premultiplied upload keeps it) lets a dye shader use one texture; split masked/unmasked frames into separate pages when each is ≥ 30 % of the area, and give mutually exclusive layers (elf vs cat ears) their own pages, or the mask half doubles GPU for frames that never dye. (aroa)
- Use a `box` 2×2 filter for lod1 by default: Lanczos looks marginally crisper at zoom 0.5 but its side-lobe noise costs ~1.5× PNG bytes; clip any filter's output to the halved box + 1 px so rects stay predictable. Identical-crop dedupe inside a (clip, dir) page only saved ~2 %. (aroa)
- **Pixel-art style toggle without re-render** (aroa A076: a settings option, done as a shader on lod1): NEAREST sampling + hard alpha (≥ 96) + 1 px outline from the 4 neighbours (darkened, undyed) + 32-level posterize only where mask = 0 keeps H4 dye exact. Same GPU/download as lod1 (baking would only save ~40 % PNG bytes; a 0.25× level was rejected). The GLSL matched the CPU reference (alpha exact, RGB ≤ 1 posterize step on ~2 % of pixels from unpremultiplying). On an iGPU (UHD 770) it cost *less* GPU than the normal LINEAR+blend path (discarded texels skip blending): plain sprite fill ≈ 1.9 ms per Mpx there, so count overdraw, not quads, and try discarding near-transparent texels in the normal shader too.
- **Metadata per lod:** split the per-set meta into a core (manifest fields + lossless per-key tables: constant / delta-coded ints / raw) and one frame file per lod, so a low-tier client fetches only lod1 rects; aroa median 8.3 KB gzip per set and lod (hats ~7, monsters ~6, bodies/faces ~18 because of per-key anchors / many layers). Make the shared shadow texture a fixed file, not "the largest shadow in this build", or the pack stops being deterministic across set lists.
- **Runtime measured with the pack** (aroa A080, UHD 770, vsync on, 200–250 players, view cap 40/80): per-(clip, dir) pages + lod1 files + worker decode (`createImageBitmap` premultiply + flipY) + a priority/LRU page registry with an upload budget + shader pre-warm gave frames > 50 ms 0–2/min (was 8–20), drawn complete 99.1–99.9 % (was 72–95), heap 150–200 MB (was 369), first download ÷6–10 vs per-clip atlases. Metadata split per (lod, clip, group) — group = '*' for layers drawn together, the layer itself for alternatives (eyes_/mouth_/ears_/face_/hair_<style>, or a manifest `layer_groups`) — with tables split by clip and rarely used anchors in a lazy per-clip file: crowd metadata 1.48 → 0.51 MB, heap −60 %, +18 % requests (chunks ~0.4 KB, needs HTTP/2); verify with a merge-back gate (chunks == v2 frames and tables). Bench trap: rank the view cap from the camera's intended centre, not `worldView` before the first render, or the client fetches metadata for the whole AOI. Measure a 'walkable' milestone (map + own character, ~1.5 MB) next to 'full view'. Accepted as the standard path (aroa A084): parallel build + split in one command; budgets 'walkable ≤ 2 MB' + 'full view ≤ 8 MB within 10 s' (low). Two dye masks on one layer (2D head face: skin + cap) pack as R / G of the existing mask half (one-mask pages stay grey and byte-identical), pairing rule `<layer>_mask` → `<layer>_*_mask` → a one-layer set's dye-block masks. Shared 2D heads (one page per expression for a whole gender) removed the low-tier pool churn entirely in a crowd (evictions 29/s → 0). Keep the last shown frame while a new page streams (turns/clip changes); a sprite pool below the crowd working set thrashes (evictions/s ≈ loads/s) and prefetch makes it worse. New per-key anchors that every frame needs (aroa: 2D-head chin socket + head roll angle, ~1 KB gzip per body) go on the split's *inline* list, which puts them in each clip's '*' chunk next to the frames (not in the core). Clients must read the pack root's inline list before fetching the lazy anchor chunks, or they download the same anchors twice. Keep one release-check command that serves any pack read-only on its own port, checks roster coverage against the pack, waits for a free iGPU, and grades every low-tier row (exit 0/1/2).
- **A clip library adds pages, not only frames:** each new clip is new (clip, dir) pages per set. With a small pool and prefetch off (aroa low tier: 160 MiB), a crowd using many different skill clips can churn the pool. Bench a "skill storm" crowd on the real low-tier GPU before enabling a library. Moving rigid layers to per-gender anchor sets shrinks the working set (aroa hats: low-tier GPU 191 → 134–146 MiB). (aroa A136, storm not yet measured)
- Memory calculator before writing render code (kit `tools/release/crowd_mem.py`): model residency per player = current clip(s) × directions seen, pack pages with the packer's own geometry from atlas.json rects (checked within 7 % of the real pack), tiers = view cap + N full look + base look for the rest. (aroa)
