# Multi-box fleet

Routes: any route with more than one box; the layer/pose details are 3d-sprite. Origin: aroa unless tagged otherwise.

Reference implementation: aroa; code in kit `tools/fleet/` (`coord.py`, `fleet.py`, `box/worker.py`, `box/gslot.sh`, schema in `tools/fleet/JOBS.md`).

## Bring-up of many boxes
1. Append ssh entries for all boxes (never edit existing `Host` blocks). (aroa)
2. **Start with 1–2 boxes**, bootstrap + verify them, then open the rest. The multi-host path was tested on fake hosts before real pods; real pods surfaced EGL, quota and network surprises. (aroa)
3. Bootstrap in phases: **setup** in parallel (probe, kit, libs, Blender, EEVEE/pin check, bandwidth, start the Hunyuan build), **seed** the first box from the reference box or local mirror once, **fan out** box-to-box (fast inside one region), **finish** (wait for the Hunyuan build + import test). Boxes that fail a phase are dropped; the rest continue. (aroa)
4. Verify once per GPU model (not per box) against the reference box's released frames; store `models/<model>.json` with the pose tag. The coordinator refuses boxes whose model has no pass for the current tag, and boxes without an ok full-concurrency benchmark (`<host>/bench.json`, ≤ 0.5 s/frame per process). (aroa)
5. **Drain before destroy:** stop new leases (empty allow lists), let in-flight sets finish or stop them by PID (decide per set from measured progress: frames written ÷ elapsed → ETA, using the frame total of a finished set of the same kind and class; keep only the ones finishing within the deadline, and kill the job shells too so no chained step starts), pull, then restart the coordinator on the new hosts: it skips layers whose pulled done-marker (current pose + spec fingerprint) and set dir exist locally, and pushes finished meshes (timings row) with a `.shared` marker instead of re-running Hunyuan. (aroa)

## Work units and scheduling
- **Unit = one item**: its Hunyuan run + icon + every layer set of it, on the same box, so meshes never travel twice. Hunyuan units are handed out first (longest-processing-time order) so every GPU starts meshing at once; Blender-only units fill free slots meanwhile. (aroa)
- **Render unit = one whole set** (item × body, every clip/dir, one Blender process). No set mixes frames from two GPU models, which is why mixed fleets are safe after per-model verify. (aroa)
- **Work stealing:** a box with < 15 min of work left asks for more: first from the pool, then unstarted units from the busiest box, then unstarted layers of a meshed unit (copy the mesh over). Slow boxes automatically get less. (aroa)
- **Leases** live in a local file, so a restarted coordinator resumes. A box unreachable for 3 rounds loses its unfinished units back to the pool. A unit that started before its lease moved may run twice; deterministic output makes that harmless. (aroa)
- Each box reads an allow-list (`item:<id>`, `layer:<tag>`, `-layer:<tag>`) whenever it changes and keeps running until the coordinator writes `finish`. (aroa)
- Send concept PNGs only to the box holding the unit; pull every 10 min from every box. (aroa)
- Static alternative without a coordinator: `--shard i/n` using precomputed LPT shard indices per box count. (aroa)
- **SSH fan-out limit:** one ssh connection per job breaks at ~40 parallel launches (sshd MaxStartups resets the extra connects). The job wrapper still printed `Blender quit` because Blender ran with a missing spec and exited, so a failed equip looked like success. Keep runner parallelism ≤ 12 per box (or multiplex with ControlMaster), and judge success by the output files (manifest present), never by the wrapper's last log line. (aroa)
- **Frozen snapshots carry their own slot script.** A snapshot frozen before a slot-manager change brings an old `blslot.sh` (no GPU pinning, legacy slot count). After syncing a snapshot to a box, copy the box's current slot script over it, and start every job with the blender binary itself (not `bash -c`), so the GPU pin can be injected. (aroa)

## Done-markers (resumable, self-invalidating)
- `state/<stage>/<key>.done` = `{secs, gpu, time, fp: {pose code, base body sha256, src}, outputs}`. A job counts as done only when the marker and its outputs exist **and** the fingerprint still matches. A changed body blend or pose code re-renders exactly the affected sets. (aroa)
- `.fail` keeps rc, log tail and attempts; `retry --stage s` clears them after the cause is fixed. (aroa)
- A task is ready only when the file it actually reads exists, not just its upstream marker. Icons read the GLB, but Hunyuan's `_tex.obj` appears before `obj2glb` writes that GLB. In aroa an icon batch of 8 started in that gap, and `import_scene.gltf` died with "Please select a file", failing all 8 (`no_frames`). The worker now also waits for `job.src`.

- **Priority only orders tasks inside one worker.** Several manifests on one box run one worker each, and they share the slots without ordering between them. To queue a later wave "after" the current one, give its items a lower priority (aroa P5) *and* start its worker with only the stages that should run now (`-- --stages hunyuan,icon`; idle Hunyuan GPU time, no Blender slots taken). Restart it with build,render when the earlier wave drains.

- **Local crashes kill local runners, not box workers.** When the local machine dies (aroa: WSL crashed twice in one release), box-side workers keep rendering, but every job driven from the local side dies: ssh-per-set runners (hair layers), pull loops and publish sequencers. The box then goes idle as soon as its own queue drains. Prefer box-side workers for long queues. Write every local driver so a re-run resumes: it skips finished sets, and its wait-for-X steps pass at once when X is already gone. Record command, PID and log in a state file. Bash reads a running script lazily, so never edit one in place. To change the rest of a running driver, kill only its bash PID (its children keep running) and start a finisher that waits on the child PID.
- **Single-copy pulls:** pulling raw renders, finalizing them into a second folder and publishing a third copy (plus a `dist` build copy) grew aroa from 22 to ~200 GB in a day. The host drive holding the WSL disk filled up and WSL crashed. To prevent it:
  - Pull in capped batches of render-done sets only (`FLEET_PULL_MAX_NEW`).
  - After each publish, delete that batch's raw and finalized copies, but only when the published copy has the same pose_version and frame count. Record the deleted tags in an rsync exclude list so the next pull skips them.
  - Keep the box copy: its done-markers need the outputs.
  - Run a box disk guard that SIGSTOPs workers below 20 GB free, and a local watchdog that SIGSTOPs the pull and publish processes and their rsync children, but not the cleanup. On WSL, watch the Windows drive that holds the vhdx as well as `/`.
- **Hung pulls:** rsync of many small raw-v1 PNGs from a box that another agent is also pulling from can stall forever with nothing transferred (aroa: 7 min stuck on a 6.7 MB set). Wrap pulls in `timeout`, kill the stuck rsync by PID so the retry loop runs, or stream `ssh box 'tar -C dir -cf - set' | tar -x`.
  - A tar stream can end early (`tar: Unexpected EOF`) and still leave a plausible-looking tree. Compare the file count with the box (`find | wc -l` on both sides) before any post-step, and re-pull on a mismatch. In aroa a post-step crashed on the truncated set's partial manifest. (aroa A113)
- **Crash-zeroed files:** a host crash in the middle of a pull or publish leaves files full of NUL bytes whose size and mtime look normal. rsync's quick check never replaces them, and a cleanup that compares only frame counts deletes the good source copy. aroa had 16 raw sets, 7 harvested hair sets and 3 published sets damaged this way.
  - After a crash, scan the trees written recently: empty files, or files whose first 16 bytes are all NUL (filter by ctime, since rsync keeps the box mtime).
  - Drop the damaged dirs and re-pull them, or re-render if the box copy was already deleted.
  - The gate must report unreadable PNGs or manifests as failures, not crash.
- **Don't `timeout` a publisher that writes its index at the end.** The aroa hair lpublish copies every harvested set (about 1,300 × 1,500 files) and writes index.json last. It took more than an hour, and `timeout 3600` killed it every time: 1,005 sets were copied but never indexed, so the cleanup kept all the raw copies. Publish in batches, writing the index per batch, or run the publisher without a timeout and watch it instead. To rescue a running one, SIGKILL only the `timeout` wrapper: the child keeps running and the driver still waits on its pipe.
- **`pgrep -f` matches its own wrapper.** In `ssh host 'pgrep -f disk_guard.sh || start disk_guard.sh'` the remote `bash -c` command line contains the name, so the check always says "alive" and nothing restarts. The same thing happened locally: a wait loop that named a publisher made the "is a publisher running?" check block for 15 minutes. Send such checks as a script on stdin (`ssh host 'bash -s' < check.sh`), anchor the pattern on the real command (`ps -eo args | grep '^bash /root/kit/fleet/x.sh'`), and keep publisher names out of ad-hoc loop command lines. (aroa)
- **Vast container restart:** the host stayed up, ssh refused connections for about 5 h, then the container came back with its filesystem intact (/workspace and /root) but every process gone. Re-run the box loops (disk guard, trim, workers) on return. A container restart doesn't lose data; a destroy does. (aroa)
- **A loop's summary line can hide a hang:** if a harvest step runs under `timeout` and prints its count only at the end, every killed pass logs nothing. Print per item, or log the start and end of each pass. (aroa)

- **Pull only your own tags, and keep one finished copy.** aroa's pull rsynced the whole box `sets_as/` for every manifest. A second manifest with another `local_root` but the same `box_root` therefore copied every wave again (37 GB), and raw → finalized → published kept each set 3×: ~200 GB in a day, until the VM disk filled the host drive.
  - Pull with a per-manifest rsync filter (`+ /<tag>/***` for its own tags, `- /<pruned>/` for tags already published and deleted locally, `- *`).
  - Prune raw and intermediate copies after a verified publish (same pose_version, same frame count). The box keeps raw output until it is destroyed, so a re-pull is possible.
  - A harvest that deletes on the box after a verified pull (aroa hair `lharvest`) also works. The "already have it" check must then accept the published copy, or a new box re-renders everything.

- **A pose bump re-queues everything already done:** done-markers fingerprint the pose code, so after a bump every old marker reads as not done and a bumped lane re-renders in full (aroa 2026-10-14, one back lane). Before pushing a bumped lane, trim its job manifest: drop every set the bump plan covers (restamped, merged or re-rendered elsewhere), keep `<manifest>.pre_<tag>`, then push. (aroa A116 `a116_v25.py trim`)
- **Pull-then-prune keeps `*/manifest.json` stubs on the box:** the worker's done check needs its outputs, so a prune that removes whole set dirs makes the worker render them again. Prune only tags that are render-done, pulled with identical files (relative path + size) and on the manifest's pose code; keep a per-wave ledger. (aroa A116; kit v3 `tools/fleet/prune_pulled.py`)
- **Old cleanup ledgers skip re-renders that reuse tag names:** a pruned-tags list or rsync exclude list from an earlier wave silently drops the new renders of the same tags. Pull a re-render wave into a fresh local root, with capped render-done pulls (`FLEET_PULL_MAX_NEW`) and `FLEET_PULL_HAVE=0` on big lanes (re-sync only tags re-rendered since the local copy; a full re-sync list took > 25 min). (aroa A116)
- **Slot-filling knobs, not step scripts:** each round, per box, free slots = gslot cap − all running Blenders (yours counted from the real processes, not the worker's queued tasks); raise your lanes' `max_blender` to fill them by priority (first / weight / last), restart exited workers with work left. A step script that set caps at fixed times left 10 of 18 slots idle for 20 min. (aroa A116 release lead; kit v3 `tools/fleet/slotfill.py`)
- **Agents can wedge mid tool call:** the lead must be able to launch any lane from the owner's documented tools alone (plan file + runner, no agent memory). Relaunch into fresh work dirs: old done markers in a reused dir skip everything. (aroa A116 release lead)

## Job manifest (schema essentials)
- Top: `version`, `wave` (box dir `/root/fleet/<wave>/`), `pose_tag` (must match the snapshot's `POSE_TAG.json` on the box), `box_root`, `local_root`, `publish_cmd`. (aroa)
- `items[]`: `id`, `kind`, `stages` (`hunyuan icon build render` on GPU boxes; `card icon2d` locally), `concept` (prepped 1024² RGBA) or `mesh`, `hunyuan` overrides, `icon` spec, `blocked_on`, `est_s`, `layers[]`. (aroa)
- `layers[]`: `tag` (unique), `base` (runtime body id = holdout), `layers`, `clips`, `dirs`, `spec` (equip spec), optional `build_py` / `render_py` with the same CLI as the default scripts, so new kinds (back, outfit, weapon swap) plug in without worker changes. (aroa)
- `blocked_on` tokens: `snapshot:<tag>` (auto-cleared when the box snapshot matches), `tool:<name>`, `body:<variant>`, approval gates. Layer-level tokens never block the item's own mesh/icon stages: 3D and icons proceed while layers wait. (aroa)
- Placeholders (`{hy_out}`, `{glb}`, `{box}`, runtime dirs) keep manifests box-independent. (aroa)

## ETA and calibration
- `plan --hosts 12x2x64:48` estimates before renting (boxes × GPUs × vCPU : VRAM). After a real run, compute measured layers/h, meshes/h and the speed factor vs `est_s` from the pulled markers (`rates.py`) and feed `--speed` / `--hy-s` back into the plan. (aroa)
- Model: Blender slot-seconds per layer set (aroa: weapon 93, shield 85, headgear 85, back 190, outfit 180; per-body head layers on a driver-locked 5090: hair ~1,400, ears ~1,200, face ~3,800), Hunyuan 90 s/mesh/process + 300 s model load, retake factors (Hunyuan ×1.15, layers ×1.1).
- **Estimating an operation (aroa docs/production/PIPELINE_COSTS.md):** per-set cost ≈ ~3 s job overhead + frames × slot-s/frame of that kind (aroa, RTX PRO 6000 at 14 slots: one-pass layers 0.15–0.25, two-render backs/splits ~0.5, multi-pass headless body 0.73, rider items 0.35 bird / 0.6 large canvas), so a one-clip re-render costs its frame share (walk 64/384 ≈ 1/6). Then stack the multipliers: items × bodies that show them × keys × 8 dirs × seats. The coverage policy (which items render on which bodies and mount seats) is the biggest lever: aroa riders cost ~3.5× the on-foot cost per hat/back and ~12× per new body; a shared 2D overlay (one hairstyle drawn at an anchor for every body and seat) costs 0 GPU. Read the per-kind seconds from the done markers of a real full-load batch: plan rates taken from small rehearsals were 1.3–2.2× too low for rider items. Budget the local side too: pull ~2.4 MB/s over a home line, publish+gate ~1.3 s/set, backup tar ~6.6 MB/s, game pack ~1 set/s on 4 workers.
- Count running renders by the command the slot wrapper actually executes: wrappers inject flags (`blender -t 8 --gpu-device N -b …`), so a `grep 'blender -b'` reports 0 while dozens of renders are running. (aroa)
- **Unattended add-on runs on a shared box:** agree a hold point with the box's queue owner (they write `<X>.done` and pause; you touch `<you>.done` or `<you>.skip` to release). Split the driver in two: a box-side watcher (setsid) that waits for the hold, renders through the slot manager with a time budget and *always* releases the queue (done on success, skip on failure or timeout), and a dev-side driver that only pulls, verifies, publishes and posts one notification. Then a dead laptop never stalls the other team. (aroa)
- **Blender exits 0 when the `--python` script fails to open or raises** (unless `--python-exit-code 1` is given), so a done marker written on rc 0 can sit over an empty output. Pass `--python-exit-code 1` and/or check the expected output files exist before writing the marker; let the dev-side check re-run entries that came back with no output, never count an error entry as checked. (aroa A072: a reversed job list built with `tr | tac` from a file with no trailing newline fused the last two tokens into a bogus pipe path. Blender exited 0 in 3 s and the set was marked done with no frames. Always end list files with a newline.)
- Dev-side drivers die with the laptop/WSL (restarts happen). Keep them idempotent: state in a JSON file, the check results merged per id, pids written down. A restart is then "check the JSON is intact, relaunch detached". (aroa)
- A pull that fails for one set leaves that set's **older** local copy in place, and a verify that globs the local dir then checks stale frames (aroa A072: one costume's split verify read pre-fix frames from an earlier run, failed, and was skipped from the publish; a re-pull fixed it). Pull with retries, then compare the local file count and newest mtime with the box before verifying; a verify failure right after an unattended re-render is first a pull problem until shown otherwise.
- **Weights location differs per box type** (aroa 2026-10-13): the old single box kept Hunyuan weights in RAM (`/dev/shm/hf`), while fleet boxes keep them where `fleet.env` says (`/workspace/.hf_home`). Any runner with a hard-coded `HF_HOME` default must read `fleet.env` first, or it silently re-downloads or fails. A box whose torch differs from the source box (2.13 vs 2.11) builds the venv instead of copying it; on an RTX PRO 6000 box that took about 3 min plus 1 min of HF weights download, so don't bother copying.
